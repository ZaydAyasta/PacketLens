## 1. Alcance normativo y resultado

Fuente de verdad: [RC1](E:/packetlens/docs/specs/SPEC-E2.1-CANDIDATE.md), RTR-03, ICMP-04, TEST-01/02 y S8; [matriz de aceptación](E:/packetlens/docs/reports/E2.1-ACCEPTANCE-READINESS.md). No se modifican especificaciones ni ADR.

Se sustituyen las excepciones provisionales de admisión por descartes de dominio con interfaz y PDU correctas. El orden es: recepción/enlace vigente → admisión MAC → restricciones IPv4 → entrega local → tránsito/posible ICMP. No se modifica el comparador DES, los retardos ni la resolución ARP normal.

| Entrada / condición | Hecho y resultado verificado |
| --- | --- |
| Llegada sobre enlace obsoleto o interfaz de entrada caída | Descarte Ethernet ordinario; **sin `FrameDelivered`** ni descarte IPv4 inventado. |
| MAC unicast ajena | `FrameDelivered` de la llegada, seguido de `DestinationMacMismatch` con la trama Ethernet original. No se procesa IPv4. |
| MAC broadcast/multicast con IPv4, incluso destino IP unicast | Pasa el gate L2 del router; luego `UnsupportedIpDestination` **IPv4**, sin alterar el destino IP. La MAC multicast no se convierte en una IP multicast. |
| Destino IP multicast, broadcast limitado o broadcast de cualquier subred propia | `UnsupportedIpDestination`, antes de TTL/Echo/LPM; cero ARP, reenvíos o errores nuevos. Incluye subred propia de interfaz caída. |
| Origen 0/8, 127/8, multicast, broadcast limitado o de subred propia | `InvalidIpv4Source`, antes de Echo o tránsito; cero emisión. |
| Error 11/0, 3/0 o 3/1, tránsito TTL0/1 | `TtlExpiredInTransit` del causante; cero error secundario, incluso con retorno disponible. |
| Error anterior, tránsito TTL64 sin ruta al destino | `NoRouteToHost` con TTL63, sin error nuevo ni ARP de retorno. |
| Echo elegible sin ruta al destino y con retorno | Un 3/0; TTL0/1 produce un 11/0. Retorno por rutas/ARP existentes. |
| Origen válido sin ruta de retorno | Solo drop del causante, sin construir/encolar otro datagrama o inventar recepción. |
| Error recibido con ruta de tránsito disponible | Puede reenviarse normalmente. Si espera ARP conserva PDU/contexto; un fallo posterior no provoca otro error. **Suprimir la respuesta de error no significa prohibir el reenvío legítimo del error recibido.** |

El nuevo tipo `DestinationHostUnreachable` / `DestinationHostUnreachableMessage` representa **entrada 3/1** para S8B y sus variantes. **No se implementa su generación por agotamiento ARP ordinario**, reservada a05b. No se añaden identificadores exteriores ficticios, protocolos, campos binarios ni presentación E2.

La clasificación usa los conjuntos **explícitos de RC1**, no el helper de configuración genérico `is_unicast`/`IsUnicast`, que rechazaba conjuntos adicionales. Multicast es224/4; no se clasifica240/4 como multicast ni una dirección remota terminada en `.255` como broadcast sin conocer su prefijo. `/31` y `/32` no tienen broadcast dirigido. No se reclama validación IP/RFC universal fuera del subconjunto modelado.

Admisión se decide **antes de encolar**: una entrada L2 de grupo, IP prohibida u origen inválido nunca llega al ARP de reenvío. No se puede fabricar legítimamente una de esas colas para probar una política tardía. C5 impide cambiar direcciones/rutas con tráfico activo; no se alteraron tablas después del estímulo para forzar supresión.

La variante posterior a ARP usa dos routers reales y cachés frías. R1 conserva datagrama recibido/interfaz/trama original y encola el paquete con TTL ya decrementado; tras ARP transmite el mismo error. R2 lo descarta por TTL o no ruta **aunque tenga retorno**, sin otro ICMP. Hay exactamente un Tx IPv4 y un drop IPv4 final en3300ns; en la variante silenciosa no hay Tx IPv4 y el error retenido se descarta en3.000.000.100ns, sin cascada. Rust comprueba además el contexto privado conservado durante la espera; C# comprueba la PDU original observada, la cola, la salida real y el descarte, y conserva `Received/Ingress` en su registro privado. No se añade API pública para inspeccionar esa cola.

Esto no completa el agotamiento de ARP de **originales ordinarios**: su decisión3/1 sigue en05b. La retención del contexto ya está disponible para ese incremento.

## 8. Calidad, complejidad y riesgos

La revisión de aserciones y brechas fue estática, apoyada por las ejecuciones: 18 métodos nuevos por motor, cero pruebas sin aserciones contando sus helpers y cero pruebas basadas solo en presencia/truthiness. Se verifican tipos/PDU completas, motivos, cardinalidad, tiempo, secuencia, estado y efectos negativos. Quitar la admisión multicast, estrechar 0/8 a una IP, omitir 127/8, clasificar `.255` remotamente o retirar la guarda de error cambia una observación explícitamente comprobada. Son contrafactuales **no ejecutados como mutantes**, no puntuaciones de mutation testing.

Se reforzaron bordes válidos/invalidos y que el Request recibido permanezca intacto aunque el descarte de tránsito tenga TTL decrementado. Igualdad entre motores y repetición no son el único oráculo: conviven con aserciones de RC1 independientes. No se añadieron pruebas de byte/checksum/OSI inexistentes.

Complejidad, sin mediciones de rendimiento:

- Clasificación de MAC y discriminante de error: **O(1)** tiempo/espacio por PDU semántica.
- Clasificación de broadcast propio: hasta dos recorridos de I interfaces, más la entrega local existente: **O(I)** tiempo y **O(1)** espacio auxiliar; se usan valores CIDR, no una tabla nueva. Acceder al dispositivo/interface mantiene el coste previo de mapas ordenados Rust o esperado constante de diccionarios C#.
- Admitir/rechazar añade a lo sumo un registro de drop. Tramas/PDUs conservan tamaño semántico fijo; la retención sigue **O(T)**, con T la capacidad existente.
- Una rama suprimida por admisión termina antes de LPM/ARP/scheduling. El coste de retorno permitido sigue siendo el de04: escaneo de rutas operativas, lookup ARP y heap **O(log Q)** por evento, sin cambiar el scheduler.
- Al agotar ARP de un error, el filtrado de M pendientes sigue **O(M)** tiempo y **O(M)** espacio transitorio; ampliar el predicado a etiquetas antiguas no altera esa complejidad ni el orden relativo FIFO.
